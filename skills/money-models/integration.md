<a id="money-models---integration-with-other-skills"></a>
# 收入模式：与其他技能整合

<a id="the-extended-hormozi-sequence"></a>
## 扩展的 Hormozi 使用顺序

```
mom-test → 100m-offers → money-models → 100m-leads
   ↓            ↓              ↓              ↓
客户探索     方案包装       变现顺序设计      流量
```

Hormozi 自己的三部曲定位为：**100m-offers**回答“卖什么”，**100m-leads**回答“怎样获得注意”，**money-models**回答“怎样让客户购买，而且足够快，使现金不再成为限制”。

| 技能 | 何时使用 |
|---|---|
| **mom-test** | 在所有步骤之前，验证问题，提取客户描述理想结果的语言 |
| **100m-offers** | 建立能转化的单个方案，本技能假设它已存在 |
| **money-models，本技能** | 安排方案顺序，让一个客户为获取下一个客户出资 |
| **100m-leads** | 引入流量；本技能决定每条线索最多能花多少钱 |

方案是基本单元，收入模式是单元的排列顺序。如果企业已有能转化的方案，但增长受现金限制，本技能就用于填补这个缺口。

<a id="skill-combinations"></a>
## 技能组合

<a id="money-models--100m-offers"></a>
### money-models + 100m-offers

这是仓库中联系最紧密的一组。Offers 打造一个难以拒绝的方案，money-models 将多个方案按时间排列。

| 100m-offers 提供 | money-models 如何使用 |
|---|---|
| 能转化的大满贯销售方案 | 作为第一阶段获客方案 |
| 叠加的价值组成部分 | 拆出部分用于功能降档，另一些作为持续订阅赠品 |
| 保证 | 作为可删除的功能，取消后降价；或作为延后付款的条件保证 |
| 高端定价 | 作为锚点，主推方案定价低于它 |

顺序：先建立能转化的方案，在熟悉你的流量中确认有效，然后围绕它构建收入模式。

<a id="money-models--100m-leads"></a>
### money-models + 100m-leads

收入模式**决定每条线索可承受的成本**。一位客户前30天产生的现金越多，可在盈利前提下承担的获客成本越高，原先太贵的渠道也就能用。

```
弱收入模式 → 可承担获客成本低 → 只有免费或低价渠道可行
强收入模式 → 可承担获客成本高 → 付费广告、联盟伙伴、代理服务都能承担
```

扩大投放前先用本技能。向漏损的收入模式灌入更多线索，只会更快亏钱。

<a id="money-models--monetizing-innovation"></a>
### money-models + monetizing-innovation

两者都触及定价，但从不同方向切入。

| 方面 | monetizing-innovation | money-models |
|---|---|---|
| 问题 | 价格和档位应该是什么？ | 以什么顺序呈现方案？ |
| 依据 | 支付意愿研究与细分 | 现金流时机与转化策略 |
| 时间尺度 | 战略层：产品与价格设计 | 战术层：本季度现金 |

**明确的冲突：折扣。**Monetizing Innovation 提醒，折扣会教会客户等待并侵蚀支付意愿；money-models 大量使用免费或折扣获客。协调方式是：只优惠**首次交易**，不动核心经常性价格。Hormozi 自己也规定：“同样的东西不要降价，要通过功能或付款条款降档。”用 monetizing-innovation 确定真实价格，用 money-models 设计不伤害核心价格的首次购买钩子。

<a id="money-models--traction"></a>
### money-models + traction

Traction 用靶心框架决定选哪个渠道；收入模式决定渠道能否算得过账。渠道并非抽象地“差”，而是对弱收入模式太贵，对强模式却合适。修好模式后，重新计算渠道账。

<a id="money-models--influence"></a>
### money-models + influence

Cialdini 的原则是这些方案内部的运作机制，这也正是伦理重要的原因。

| 方案机制 | 影响力原则 |
|---|---|
| 达标返款、带处罚条件的试用 | 承诺与一致性、损失厌恶 |
| 赠品、“惊喜与愉悦”、免费入门指导 | 互惠 |
| 赠奖获胜者、“10人中8人选高端” | 社会认同 |
| 截止日期、仅一次抵扣升级、限制报名 | 稀缺性 |
| 锚点升级、“惊讶反应” | 锚定与对比 |

用 influence 理解为什么有效，并使做法留在伦理边界内，参见下文冲突部分。

<a id="money-models--spin-selling"></a>
### money-models + spin-selling

B2B 或高接触销售中，方案顺序必须融入对话，而非只放在结账页。SPIN 搭建谈话结构，money-models 提供提出方案的时机。

| SPIN 阶段 | 收入模式中的时机 |
|---|---|
| 背景与问题提问 | 找出获客方案已解决的问题，以及接下来的问题 |
| 影响提问 | 建立升级方案回应的需求，“没有Y就无法拥有X” |
| 需求收益提问 | 提供升级；如果被拒绝，进入降档阶梯 |

降档阶梯很自然地对应 B2B 异议处理；“1—10分”的意愿温度检查也与 SPIN 的承诺探索相容。但节奏要慢，一通电话连续提出9个付款方案，在企业销售中会显得咄咄逼人。

<a id="money-models--lean-startup"></a>
### money-models + lean-startup

“一次完善一个方案”就是小批量思维。每个方案都是假设，应先跑到可靠，完成构建—衡量—学习循环，再加下一个。“逐步提价，直到拒绝的损失超过接受的收益”是把创新核算用于定价。不要一次推出四阶段模式，那是可能压垮业务的大批量发布。

<a id="conflicts-and-tensions"></a>
## 冲突与张力

<a id="conflict-1-aggressive-urgencypenalty-tactics-vs-ethical-influence-lines"></a>
### 冲突1：激进紧迫感与处罚，和影响力伦理边界

**Hormozi：**带处罚的试用、取消费用、“取消入口可找到但别太容易”、仅一次抵扣升级。

**Cialdini 与信任经济：**人为稀缺、胁迫承诺会侵蚀信任，并招致暗黑模式监管。

**解决：**Hormozi 自己也划了底线：不愿让你留钱的人就退款，强卖是弱产品表现，保持透明。费用须与真实价值对齐，例如用于真实上手服务；事先披露自动续费，并让取消真正容易。如果策略只有在客户没理解时才有效，就既不符合 Cialdini 的伦理检验，也过不了法律关。

<a id="conflict-2-premium-price-philosophy-offers-vs-freediscount-attraction-here"></a>
### 冲突2：Offers 的高端价格哲学，与本技能的免费或折扣获客

**100m-offers：**收取溢价，价格传递价值，不打价格竞争。

**money-models：**用免费、1美元、赠奖、买X送Y吸引客户。

**解决：**两者并不真正冲突。**只优惠首次交易，不优惠核心价格。**升级、持续订阅及以后每次报价都保留高端价。钩子是一项获客成本，不是重新给产品定价。

<a id="conflict-3-30-day-payback-vs-saas--long-cycle-reality"></a>
### 冲突3：30天回本，与 SaaS 或长周期现实

**Hormozi：**30天内收回获客与服务成本。

**现实：**SaaS 回本常为6—12个月以上，企业交易可能持续几个季度。

**解决：**把30天当作**方向，而非门槛**。允许时通过年付、上手或启动费、批量购买提前现金；不允许时，接受真实的更长回本周期。逐个建立“获客→升级→降档→持续订阅”的顺序逻辑，即使30天数字不适用，仍可迁移。

<a id="conflict-4-everybody-buys-something-downsell-everything-vs-qualification"></a>
### 冲突4：“人人都要买点什么”，与客户筛选

**Hormozi：**把每个“不”变成小一点的“是”。

**现实：**有些潜在客户应该放走；过度转化会带来不匹配、高投诉的客户。

**解决：**Hormozi 部分认同：“不愿留卡、不愿投入行动的人，我不会卖给他。”降档是为了匹配，而非强迫。超出真实预算或意愿成交的客户，会流失、退款并给差评，抵消新增销售。

<a id="conflict-5-continuity-as-recurring-value-vs-continuity-as-lock-in"></a>
### 冲突5：持续价值，与订阅锁定

**奖励型**持续订阅，例如赠品、折扣，能够对齐利益；**费用或处罚型**持续订阅，例如免启动费、取消费，可能变成束缚。

**解决：**Hormozi 自己偏好奖励，并提醒“超过5%想提前取消，就该调查”。人们想离开，问题就在产品；用费用把他们困住，只会把流失变成怨恨与差评。

<a id="when-money-models-is-the-wrong-tool"></a>
## 什么时候不该用收入模式技能

- **还没有能转化的方案：**用100m-offers，尚未验证时用mom-test。顺序无法拯救没人要的方案。
- **没有流量来源：**用traction或100m-leads，收入模式需要线索。
- **纯定位或品类困惑：**用obviously-awesome。
- **战略定价或档位设计：**用monetizing-innovation。
- **企业或委员会销售：**用spin-selling，快速降档阶梯不适合长周期。
- **受监管或信任优先的类别：**处罚和自动续费的法律与声誉风险可能大于现金收益。
- **真正一次性、无法重复的购买：**没有持续订阅可加，应最大化单次购物篮。

<a id="the-dependency-map"></a>
## 依赖关系图

```
探索层：      mom-test → spin-selling
                  ↓
战略层：      obviously-awesome / monetizing-innovation / blue-ocean
                  ↓
方案层：      100m-offers，建立能转化的基本单元
                  ↓
变现层：      money-models，本技能，为现金安排单元顺序
                  ↓
流量层：      traction → 100m-leads，提高每条线索可承受成本
                  ↓
影响力层：    influence，每个方案内部的机制
```

money-models 位于方案构建与流量之间。它假设上层已有能转化的方案，并为下层流量提供经济基础。如果方案层还没解决，先回到上层。
