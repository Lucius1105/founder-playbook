<a id="mom-test---integration-with-other-skills"></a>
# Mom Test——与其他技能的结合

<a id="sequencing-with-other-skills"></a>
## 与其他技能的使用顺序

```text
mom-test → 100m-offers → money-models → 100m-leads
   ↓             ↓              ↓              ↓
  需求探索      方案包装         商业变现         流量获取
```

| 阶段 | 使用技能 | 原因 |
|-------|-----|-----|
| 尚未验证 | mom-test | 找到值得解决的问题 |
| 已验证，但没有销售方案 | 100m-offers | 包装解决方案 |
| 已验证，有销售方案，但增长受现金制约 | **money-models** | 安排销售顺序，让每位客户的收入支持获取下一位客户 |
| 已验证，有销售方案 | 100m-leads | 获取流量 |

如果企业有产品却没有付费客户，几乎总是缺少销售方案设计这一步（第 2 步）。

<a id="skill-combinations"></a>
## 技能组合

<a id="mom-test--100m-offers"></a>
### mom-test + 100m-offers

Mom Test 提取客户谈论理想结果时使用的真实语言。设计销售方案的价值主张时，直接采用这些原话。

| Mom Test 的输出 | 100m-offers 的输入 |
|-----------------|-------------------|
| “手工做报告每周浪费我四个小时。” | 时间延迟杠杆（缩短） |
| “上季度我差点被开除。” | 理想结果（明确利害关系） |
| “这件事我每月付外包人员 1,500 美元。” | 价格参照与总价值计算 |
| 对话中提到的 15 个障碍 | 第 2 步的障碍清单，不必凭空编造 |

<a id="mom-test--spin-selling"></a>
### mom-test + spin-selling

SPIN Selling 为面对面的企业销售会谈组织问题；Mom Test 为早期想法验证组织问题。两者有共同基础——过去行为、问题—影响—需求回报——但服务于不同阶段。

| 问题类型 | Mom Test | SPIN |
|---------------|----------|------|
| 背景 | “带我过一遍你这一周。” | 情境问题 |
| 痛点 | “什么都不做的代价是什么？” | 问题与影响问题 |
| 方案匹配 | “你试过解决这个问题吗？” | 需求回报问题 |
| 承诺 | “你愿意为此出钱吗？” | 成交／推进 |

用 Mom Test 做需求探索访谈。一旦已经有产品，要向具有明确采购流程的客户销售，就切换到 SPIN。

<a id="mom-test--obviously-awesome"></a>
### mom-test + obviously-awesome

Mom Test 揭示哪个客群才是“真正适合的那群人”；Obviously Awesome 为这个客群定位。顺序是：访谈 → 找出痛点最强、付费意愿最高的客群 → 围绕他们理解世界的方式定位。

<a id="mom-test--crossing-the-chasm"></a>
### mom-test + crossing-the-chasm

Crossing the Chasm 区分早期采用者与主流客户的行为。如果只与早期采用者交谈，Mom Test 访谈也可能误导你，因为两者需求不同。应分别对两群人使用 Mom Test，标明属于哪一类，不要把结果取平均。

<a id="conflicts-and-tensions"></a>
## 冲突与张力

<a id="conflict-1-dont-tell-them-what-their-problem-is-vs-domain-expertise"></a>
### 冲突 1：“不要告诉他们问题是什么”与领域专业知识

**Mom Test 规则：**问题归他们，不要替他们说话。

**现实：**在医疗、技术、监管等行业，客户可能确实缺少表达问题所需的词汇或框架。放射科医生能描述症状，却未必能表达为“我们需要一个自动优先处理紧急扫描的工作流工具”。

**处理方式：**从开放问题开始。如果对方描述的工作流明显存在问题，可以谨慎命名：“听起来 X 拖慢了你的速度，是这样吗？”不要强加结论：“你需要一个 X 工具，对吧？”

<a id="conflict-2-mom-test-caution-vs-lean-startup-speed"></a>
### 冲突 2：Mom Test 的谨慎与精益创业的速度

**Mom Test：**谨慎，不要推销，花几周了解。
**Lean Startup：**快速运行构建—衡量—学习循环。

**处理方式：**两者并不对立。Mom Test 访谈是构建—衡量—学习的补充。用 Mom Test 做探索循环——“什么问题重要？”——用 Lean Startup 做验证循环——“我的方案有用吗？”

不要没完没了地用 Mom Test 访谈来逃避开发，也不要借 Lean Startup 的名义跳过倾听。

<a id="conflict-3-talk-less-vs-salesclosing-skills"></a>
### 冲突 3：“少说”与销售／成交能力

**Mom Test：**你说得越多，做得越差。
**销售：**说服需要把价值讲清楚。

**处理方式：**区分阶段。需求探索时（Mom Test），多听少说；销售时——已经有产品并验证了市场之后——把价值讲清楚。不要混在一起。一场偷偷变成推销的“需求探索会谈”，两件事都做不好。

<a id="conflict-4-hypothesis-driven-vs-ethnographic"></a>
### 冲突 4：假设驱动与民族志观察

**假设驱动：**形成具体判断，设计问题检验它。
**民族志观察：**不带预设地观察。

**处理方式：**Mom Test 偏向民族志观察，但接受假设。关键是有假设却不诱导证人。例如，“我认为创始人在 X 上遇到困难” → “带我过一遍你这一周”（开放观察），然后看对方是否在没有提示时主动提到 X。

如果必须引导对方才说到你的假设，这个假设很可能是错的。

<a id="when-to-stop-using-mom-test"></a>
## 什么时候停止使用 Mom Test

出现以下情形，说明你已经越过需求探索阶段：

- 多个人用相似的话描述同一个问题。
- 你能预测下一次访谈的答案。
- 人们开始付费或作出付费承诺（定金、意向书、真金白银）。
- 你能说出一个明确、具体、找得到的客群。
- 至少有一位早期核心客户主动催你把产品做出来。

此时应从访谈转入开发，并用销售会谈（SPIN 等）替代需求探索对话。

<a id="anti-pattern-ive-done-50-interviews-and-still-dont-know-what-to-build"></a>
## 反面模式：“做了 50 次访谈，还是不知道该做什么”

这是客户细分的问题，不是问题质量的问题。第 51 次访谈不会有帮助。

**修正方式：**停止访谈，回看笔记。找出痛苦最切身、代价最高、问题最具体的客群，只重新访谈这一群人。几乎总会发现，你一直把三个以上客群混在一起，最后平均成了一团模糊信息。
