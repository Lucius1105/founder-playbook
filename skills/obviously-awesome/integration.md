# Obviously Awesome——与其他技能结合

<a id="skill-integration-table"></a>
## 技能协同表

| 技能 | 关系 |
|------|------|
| **Mom Test** | 先使用：为解决方案定位之前，先验证问题。 |
| **Crossing the Chasm** | Chasm 选择滩头市场，OA 在该市场中定位。两者结合：Chasm 负责战略目标选择，OA 负责战术信息表达。 |
| **Blue Ocean Strategy** | BOS 重新定义竞争游戏，OA 在选定游戏中定位。如果现有品类是一种陷阱，先用 BOS，再用 OA 传达价值。 |
| **Monetizing Innovation** | OA 第六步的价值主题，为 MI 的价值定价提供依据。 |
| **$100M Offers** | OA 定位与 Hormozi 的价值叠加互补：先面向正确市场定位，再在该框架内叠加价值。 |
| **$100M Money Models** | OA 确定战略框架，即你能赢得谁、为什么；money-models 将框架内的报价方案排序，以加快现金回笼。先定位：品类不清晰时，回本再快的报价阶梯也卖不出去。 |
| **$100M Leads** | OA 告诉你在广告／内容中说什么，Leads 告诉你如何获取流量。 |
| **SPIN Selling** | OA 提供战略框架，SPIN 提供框架内的战术销售对话。 |
| **Influence** | 来自 OA 所选细分市场的权威性与社会认同，为 Cialdini 式说服提供定位证据。 |

<a id="honest-conflicts"></a>
## 需要正视的冲突

<a id="oa-says-subsegment-is-often-the-winner-blue-ocean-says-niche-is-trap-8"></a>
### OA 认为细分往往能取胜；Blue Ocean 认为利基是第八个陷阱

**这是实质性的理念冲突。** 两者对“利基”的定义不同：
- **OA 的“细分市场”**＝定义明确、你能成为领导者的市场，即“小池塘里的大鱼”。
- **BOS 的“利基陷阱”**＝别人忽略的小块红海，仍然是红海，只是更小。

**处理方式：** 检验“这个细分市场是否增长？是否存在共同的未满足需求？你能主导它吗？”如果答案是肯定的，就采取 OA 的“大鱼”策略。如果只是“在糟糕市场里找个安静角落”，则落入 BOS 所说的陷阱。

<a id="oa-says-1-4-value-themes-less-is-more-100m-offers-says-stack-6-bonuses-more-is-more"></a>
### OA 主张 1—4 个价值主题，少即是多；$100M Offers 主张叠加 6 个以上赠品，多即是多

**理念相反，优化对象不同：**
- **OA：** 追求定位清晰，越少越容易占据明确的心智位置。
- **Hormozi：** 追求报价方案的感知价值，更多意味着更大的价值组合。

**处理方式：** 在定位层面使用 OA，以 1—4 个主题明确品类适配；在报价方案层面使用 Hormozi，在该定位框架内叠加价值。不要混淆市场定位和报价方案构建。

<a id="oa-says-best-fit-customers-hold-the-key-crossing-the-chasm-says-visionaries-are-terrible-references-for-pragmatists"></a>
### OA 认为最匹配客户掌握答案；Crossing the Chasm 认为愿景者是实用主义者的糟糕参考

**对处于鸿沟阶段的产品，这是关键冲突。** 如果尚未跨越鸿沟，“最匹配客户”又是愿景者，采用 OA 方法就会形成吸引更多愿景者的定位——与你跨越鸿沟所需的方向相反。

**处理方式：** 先用 Crossing the Chasm 识别由实用主义者组成的滩头细分市场，再用这些目标实用主义者，或推演出的实用主义者画像，作为最匹配客户信号来源，应用 OA 方法。

<a id="oa-says-focus-on-best-fit-customers-mom-test-says-talk-to-anyone-with-the-problem"></a>
### OA 主张聚焦最匹配客户；Mom Test 主张与任何有该问题的人交谈

**没有真正冲突。** Mom Test 是方法论，解决怎么谈；OA 是分析方法，解决更重视谁的回答。访谈 OA 的最匹配客户时，使用 Mom Test 方法即可。

<a id="oa-mentions-check-in-periodically-crossing-the-chasm-says-dont-broaden-beachhead-prematurely"></a>
### OA 提到定期检查；Crossing the Chasm 反对过早扩大滩头市场

**实际上不冲突。** OA 涉及战术信息表达的更新；Chasm 涉及战略目标选择的纪律，范围不同。

<a id="when-oa-is-less-critical"></a>
## OA 没那么关键的情况

对“定位是一切基础”的现代反例：

| 公司 | 胜出因素（定位居于其次） |
|------|------------------------|
| TikTok | 算法 + 内容分发 |
| Stripe | 开发者体验 + API 质量 |
| OpenAI / ChatGPT | 产品能力带来的震撼 |
| Linear | 产品打磨 + 设计 |
| Cursor | 优于 Copilot 的 AI；通过 Twitter 口碑传播 |
| Figma | 浏览器内协作 + 免费层；网络效应 |

**共同模式：** 当产品确实好十倍，或有强网络效应，或以产品驱动增长时，定位依然重要，但不决定胜负。

**OA 框架最有力的场景：**
- 已有成熟竞争品类的 B2B 科技产品。
- 并非全面好很多，而是在不同方向上更好的产品。
- 销售人员需要解释产品的销售驱动型企业。
- 陷入同质化竞争的公司。

**没那么关键的场景：**
- 用户体验不言自明的产品驱动增长产品。
- 使用规模会滚雪球增长的网络效应产品。
- 真正革命性的能力，例如 AI 原生能力。
- 纯品牌／内容业务。

<a id="why-this-skill-matters-now"></a>
## 为什么这个技能在当下重要

**OA 应对的现代挑战：**

<a id="multi-product-companies-critical-rule"></a>
### 多产品公司：关键规则

每个产品都需要自己的定位。公司可以有定位，各个产品也有自己的定位，不要混淆两者。

例如：
- Microsoft（公司）≠ Word ≠ Excel ≠ Teams ≠ Azure。
- AgentSeal（公司）≠ CodeBurn（产品）。

<a id="competitor-positioning-attacks"></a>
### 竞争对手的定位攻击

当竞品用错误方式定义你，例如“他们的 codeburn 对比我的安全版本”，掌握自身定位的主导权就很重要。OA 框架提供了拒绝对方框架的工具。

<a id="category-disruption"></a>
### 品类颠覆

新技术改变品类边界时——AI 正在各领域这样做——定位会成为生存问题。旧定位可能几天内就变成包袱，而不是几年。

<a id="crowded-markets"></a>
### 拥挤的市场

每个开发者工具品类都有 50 个以上竞争者。定位决定你是“显而易见的选择”，还是“又一个需要评估的工具”。
