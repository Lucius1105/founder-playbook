# Crossing the Chasm——案例研究

本文件详述 [SKILL.md](SKILL.md) 引用的案例。Documentum 是经典的保龄球瓶式扩展案例。

<a id="documentum---the-bowling-pin-beachhead"></a>
## Documentum——保龄球式滩头市场

书中展示滩头选择的最佳完整案例。

<a id="the-setup"></a>
### 背景

Documentum 需要在文档管理领域找到滩头。团队锁定制药行业的监管事务部门，全行业约 40 个部门、合计约 1,000 人。

<a id="why-it-was-a-good-beachhead"></a>
### 为什么是好滩头

- **单一、可识别的经济决策者：** 各制药企业的监管事务副总裁。
- **现在就必须购买的理由：** FDA 提交期限要求行动；延迟数天就可能因市场独占期损失而损失数百万美元。
- **三个月内可交付完整产品：** Documentum 能提供完整解决方案。
- **尚未设防：** 没有现有厂商主导这一利基。
- **保龄球潜力：** 相邻利基清晰可见。

<a id="the-bowling-pin-progression"></a>
### 保龄球式推进

```
制药监管事务：40 个部门，约 1,000 人
            ↓
            研究人员：同一制药公司的研发团队
            ↓
            生产车间：流程文档
            ↓
            工厂建设与维护：工程文档
            ↓
            受监管的化工业：相似监管机制
            ↓
            炼油厂：健康、安全与环境文档
            ↓
            华尔街互换交易：合规文档
```

每个球瓶中的实用主义者，都参考前一个球瓶中的实用主义者，垂直口碑发挥作用。

<a id="the-lesson"></a>
### 启示

仅 1,000 人的小滩头，发展为数十亿美元公司。**头瓶大小不重要，痛点与后续扩展潜力才重要。**

<a id="lotus-notes---sheldon-laube-and-price-waterhouse"></a>
## Lotus Notes——Sheldon Laube 与 Price Waterhouse

愿景者做出承诺的经典案例。

<a id="the-setup-1"></a>
### 背景

1980 年代末，Lotus Notes 是一种新的群件概念，多数企业尚无“协作软件”的概念。

<a id="the-visionary"></a>
### 愿景者

Sheldon Laube 是 Price Waterhouse 的 CIO。他看到 Notes 对分布式审计团队的潜力，在产品尚未完成时，就承诺购买 **10,000 个席位**。

<a id="why-this-mattered"></a>
### 为什么重要

- 愿景者就是这样：在账尚未完全算得通前做出承诺。
- Price Waterhouse 成为支撑 Notes 早期市场的标杆客户。
- 没有 Sheldon Laube 这样的人，就没有早期市场。

<a id="why-it-failed-long-term"></a>
### 为什么长期失败

Notes 从未跨越进入大众协作市场的鸿沟，最终输给邮件加互联网协作工具，是未能转型为平台的应用。

<a id="the-lesson-1"></a>
### 启示

- **愿景者让早期市场成为可能。** 找到他们，珍惜他们。
- **愿景者不会自动把你带到实用主义者那里。** 仍须单独完成跨越鸿沟。

<a id="steve-jobs-and-xerox-parc"></a>
## Steve Jobs 与 Xerox PARC

第二种愿景者承诺原型。

<a id="the-setup-2"></a>
### 背景

1979 年，Xerox PARC 已开发图形用户界面、鼠标、位图显示等革命性技术，Xerox 自己却不知道如何商业化。

<a id="the-visionary-1"></a>
### 愿景者

Steve Jobs 参观 PARC 后，立刻理解这些技术的战略意义。他取得相关概念的许可，并让 Apple 投入图形操作系统，后来发展成 Lisa 和 Macintosh。

<a id="why-this-mattered-1"></a>
### 为什么重要

没有 Jobs 的愿景承诺，GUI 可能还会在 Xerox 内部停留十年。Apple 的投入迫使技术成为商业产品。

<a id="the-lesson-2"></a>
### 启示

愿景者是从研究实验室到市场的桥梁。他们在应用场景尚未被广泛理解时，对技术做出战略下注。

<a id="silicon-graphics---hollywood-post-production"></a>
## Silicon Graphics——好莱坞后期制作

发挥完整产品效益的成功故事。

<a id="the-setup-3"></a>
### 背景

Silicon Graphics 的工作站是性能强、价格高的 Unix 机器。没有滩头，就要与 Sun、HP 正面竞争。

<a id="the-beachhead"></a>
### 滩头

好莱坞后期制作，具体包括大型制片厂的数字剪辑、特效和 3D 动画。

<a id="why-it-worked"></a>
### 为何奏效

- **市场替代方案：** 传统模拟电影剪辑设备；Avid 正在崛起，但仍较小。
- **产品替代方案：** 定位为通用机器的 Sun、HP Unix 工作站。
- **迫切购买理由：** 《侏罗纪公园》等电影需要 Sun 无法提供的 CGI 能力。
- **完整产品：** SGI 专门为电影制片厂整合合适的软件、培训和支持。

<a id="the-result"></a>
### 结果

SGI 主导好莱坞后期制作十年。1990 年代几乎所有大量采用 CGI 的重要电影都使用它。

<a id="why-it-eventually-lost"></a>
### 最终为何失利

它是应用滩头，而非平台。当 Intel + Linux + 同质化工作站在性能上追平 SGI，完整产品优势随之崩塌。这是典型的应用与平台陷阱。

<a id="the-lesson-3"></a>
### 启示

利基主导地位真实且持久，直到通用产品层出现同质化。用跨越鸿沟赢得市场，随后规划平台转型。

<a id="quicken---the-paper-checks-beachhead"></a>
## Quicken——纸质支票滩头

一个消费软件案例。

<a id="the-setup-4"></a>
### 背景

1980 年代末已有个人财务软件，但仍是小众。多数人用纸质支票和登记簿管理财务。

<a id="the-beachhead-1"></a>
### 滩头

为有条理的中产家庭替代纸质支票管理。

<a id="why-it-worked-1"></a>
### 为何奏效

- **市场替代方案：** 纸质支票，即 Quicken 争取的预算来源。
- **产品替代方案：** Andrew Tobias 的 Managing Your Money，定位为高阶用户工具。
- **完整产品：** Quicken 更简单，与银行集成，交付连贯的登记簿替代工作流。

<a id="the-positioning-approach"></a>
### 定位方法

Quicken 针对纸质支票簿这一市场替代方案定位，而非针对竞品软件。它面向不满手工财务管理的小企业与忙碌个人，强调简单性与银行集成，以区别于既有方案 Andrew Tobias 的 Managing Your Money。

<a id="the-lesson-4"></a>
### 启示

针对市场替代方案，例如普遍存在、平凡无奇的纸质支票定位，有时比针对产品替代方案更有力。市场替代方案明确了你要争取的预算。

<a id="channelpoint---insurance-agent-systems"></a>
## Channelpoint——保险代理人系统

<a id="the-setup-5"></a>
### 背景

Channelpoint 在 1990 年代销售保险代理人管理系统。

<a id="the-beachhead-2"></a>
### 滩头

受理、报价、承保流程失效的独立保险代理人。

<a id="the-positioning"></a>
### 定位

| 项目 | 内容 |
|------|------|
| 目标客户 | 独立保险代理人 |
| 市场替代方案 | 传统总代理，即手工纸质工作流 |
| 产品替代方案 | Yahoo!／SABRE，定位为横向旅游／信息平台 |
| 完整产品 | 保险专属报价承保工作流 + 保险公司集成 |

<a id="the-lesson-5"></a>
### 启示

即使在复杂、受监管的行业，滩头方法也有效。选定利基，构建完整产品，取得主导。

<a id="microsoft---the-exception-that-proves-the-rule"></a>
## Microsoft——印证规则的例外

Microsoft 从未遵循利基／诺曼底登陆战略，而是采用**“Evel Knievel 特技飞越法”**，完全忽略鸿沟。

<a id="why-it-worked-for-them"></a>
### 为什么对它有效

- Windows、NT、IE 是继承自 IBM 的 PC 操作系统版图的延伸。
- “出生在 IBM 创造的需求龙卷风中”。
- 快速跟随，而非先行：Windows 跟随 Mac，IE 跟随 Netscape。
- 掌握客户端，是“鸿沟实用主义者一侧的永久飞地”。

<a id="why-you-cannot-copy-this"></a>
### 为什么你不能复制

没有 IBM 级别的平台继承优势，鸿沟对你就是真实的。Microsoft 的打法无法被初创企业复制，不要被其公开可见的成功误导。

<a id="the-lesson-6"></a>
### 启示

看似反驳鸿沟理论的案例，通常有独特条件。模仿之前先检查。

<a id="the-death-by-tornado-companies---wang-lotus-notes-macintosh-silicon-graphics"></a>
## “死于龙卷风”的公司：Wang、Lotus Notes、Macintosh、Silicon Graphics

这四家公司都成功跨越过各自鸿沟，却都因同一原因衰亡或停滞。

<a id="the-pattern"></a>
### 模式

1. 跨越鸿沟进入垂直市场，例如 Wang 的文字处理、SGI 的后期制作。
2. 多年主导该利基。
3. 底层技术同质化时，未能转型为平台。
4. 输给横向竞争者：PC、互联网、Windows、Sun／Intel。

<a id="the-mechanism"></a>
### 机制

**应用适合跨越鸿沟，平台适合大众市场。** 跨越后停留在垂直领域太久，就会被采用横向策略的平台竞争者吞噬。

<a id="the-lesson-7"></a>
### 启示

跨越鸿沟必要，但并不充分。取得滩头后，必须正确解读信号：
- 如果垂直优势仍在，就在相近垂直领域继续保龄球式扩展。
- 如果同质化将至，就转型为平台。
- 如果两条路都走不通，就趁还能出售时出售。

上述四家公司错过了转型。

<a id="pragmatist-whole-product-wins-why-inferior-beats-superior"></a>
## 实用主义者的完整产品赢家：较差产品如何战胜更好产品

| 实用主义者选择 | 而非 | 原因 |
|----------------|------|------|
| Intel | Digital alpha | 完整产品生态 |
| Windows NT | Linux | 书籍、培训、支持 |
| Oracle | Sybase | 兼容工具的后续配套市场 |
| Microsoft Word | WordPerfect | 标准化 |
| HP 打印机 | Lexmark | 生态 |

<a id="the-lesson-8"></a>
### 启示

每个案例中，赢家的**通用**产品较差，**完整**产品更好。实用主义者优化的是完整产品完备度，而非功能清单。

如果你输给“较差”竞品，应检查完整产品完备度，而非功能对比。对方很可能拥有更好的书籍、培训、伙伴、集成、认证、支持与生态。

<a id="counter-example---when-the-niche-has-no-follow-on"></a>
## 反例：利基没有后续扩展

<a id="the-setup-cautionary"></a>
### 背景：警示性情境

初创企业选了定义清楚的滩头，并拿下它。但该利基没有相邻联系，没有第二个球瓶可击倒。

<a id="the-problem"></a>
### 问题

你为一个利基投入 18 个月构建完整产品，拿下 60% 份额，却无法进入其他实用主义者群体，因为他们的行业不参考你的行业。

<a id="the-outcome"></a>
### 结果

你成为小市场里的生活方式型企业。有时这没问题；有时投资者期待 100 倍回报，而你让他们停在原地。

<a id="the-lesson-9"></a>
### 启示

九要素选择表包含“下一目标客户”是有原因的。**这个球瓶必须连向下一个。** 孤立利基即便拿下，有时仍是陷阱。

<a id="when-not-to-cross---stay-in-early-market"></a>
## 何时不跨越：留在早期市场

> “有时正确答案就是不要跨越。不要尝试跨越，也不要尝试增长。留在早期市场模式，保持低烧钱率，继续寻找。”

这是增长战略书籍中少见的思想诚实。有些产品永远找不到可跨越的滩头。强行跨越，比保持小规模更快杀死公司。

<a id="diagnostic-questions"></a>
### 诊断问题

- 是否构建了 20—50 个客户场景，却没有一个通过九要素测试？
- 是否所有候选利基的经济决策者都不明确？
- 是否所有利基都已被竞争者牢固设防？
- 是否没有任何利基能在三个月内完成完整产品？

若多项为是，**不要尝试跨越。** 留在早期市场，保持低烧钱率，寻找更好的滩头，或承认这是一家生活方式型企业。
